# protocol

`protocol/protocol.sh`

Installs and manages [protocol](https://github.com/malahmen/protocol), the conversion API every converter sits behind. You hand it a document; it answers `202` and an ID at once, converts in the background, and announces the result on a completion stream. marker (PDF and images, with OCR) and markitdown (Office and the rest) each get their own queue, and marker's queue is split by expected cost into a light and a heavy lane, so a small document never waits behind a book.

- **Target**: **Podman** only - rootless, one Quadlet unit per process under the user's systemd, with lingering so it starts at boot without a login (Linux; podman 4.5 or later). The marker worker runs inside protocol-droid's marker image, built on the same host, so the host that builds is the host that runs: corelia.
- **Six units**: `protocol-api` (the HTTP API, port 8090), `protocol-marker-light` and `protocol-marker-heavy` (one worker per lane), `protocol-markitdown`, `protocol-transcription`, and `protocol-maintenance` (removals and prunes). The transcription worker runs in the API's image and sends audio to Speaches on this host (`speaches.sh`) at `http://host.containers.internal:8000` - from a rootless container on corelia the LAN address `192.168.3.46:8000` is refused. Empty that setting and the API refuses audio instead of queueing it where nothing takes it. An unreachable Speaches is a warning in `status`, not a reason to refuse `install`: it serves one converter.
- **Images, built from source**: `build` (and `install`, when an image is missing) clones protocol-droid and protocol, fetches `main`, and builds from that commit - never from a working copy, which may hold uncommitted work. protocol-droid's `marker-service` and `markitdown-service` are built first; protocol goes on top of each. Every image is labelled with its commit, and `status` shows it. The first marker build compiles llama.cpp and installs torch: a long wait, and 6.8 GB.
- **What it stores into** is not created here: the registry database and a Redis of protocol's own on meksha, and two buckets on Garage on the NAS, made by kuat's `protocol_stores` role and by hand. `install` checks that every one is reachable before it writes or starts anything: a configuration that fails the check never becomes a unit, so it cannot start at the next boot either.
- **Secrets**: five credentials from kuat's vault - `protocol_db_password`, `protocol_redis_password`, `protocol_s3_access_key`, `protocol_s3_secret_key`, `qdrant_api_key`. `install` asks for each missing one once (`secrets` replaces one) and keeps it as a podman secret, which reaches the containers as an environment variable: never in a unit file, a settings file or a command line.
- **marker's models**: downloaded into the volume `protocol-models` on the first start (1.8 GB). Both marker workers share it at one fixed SELinux level - surya keeps the downloading container's own SELinux categories on every file it moves into the cache, so under per-container levels one worker could not read the other's downloads. The light worker starts first and the heavy one once it is taking jobs, so the two never download the same model at once.
- **Qdrant collections**: empty until ingestion exists and names the collections it writes. Until then removal deletes no vectors, and the log and `status` say so.
- **Network exposure** (Kamino 235): the API is a LAN service - Padme and n8n submit to it from other machines - so its port is published on **every interface (`0.0.0.0`) by default**, deliberately, and `install` says so. `SCOMP_BIND_ADDR` overrides it at install: `127.0.0.1` keeps it on this machine (no LAN URL, no firewall offer), one LAN address of this host publishes it only there. The `protocol-api` unit's `PublishPort=` carries the address; it is saved (`PR_BIND_ADDR` in `protocol.conf`) so `status`, `test` and the URLs follow it.
- **Firewall**: `install` offers to open the API's port in firewalld or ufw (not when published on loopback only); a port inside an open range (corelia opens 1025-65535) reads as open.
- **Settings** (`config`): the API port, MariaDB host and port, Redis URL, S3 endpoint and buckets, Qdrant URL and collections, the Speaches URL, the models volume, the branch to build and both repositories. Each value is checked for what it is (Kamino 236): ports 1-65535; the MariaDB host a host name or IPv4 address; the Redis URL `redis://` or `rediss://` host[:port][/db] with no credentials (the password is a secret); the S3 endpoint, Qdrant and Speaches URLs `http(s)://` host[:port][/path], no credentials, no query (Speaches may be empty); the buckets by the S3 naming rules; the collections comma-separated names (the spaces typed after commas go) or empty; the models volume a volume name, never a path (that would bind-mount this host's files); the repositories an `https`/`git`/`ssh` URL, `user@host:path` or an absolute path - never a transport like `ext::`, never a token in an https URL; the branch a git branch or tag name, not starting with `-`. A value that is not one of these is refused with what was expected. A changed repository is the one fetched from next build, and git is handed the ref and repositories after `--`, so none is ever read as an option.
- **The settings file is parsed, never sourced** (Kamino 236): `protocol.conf` is read with `conf_load` (`scripts/_common/conf.sh`), so a `$(...)`, a backtick or a line of shell in it runs nothing. Each key goes through the same checks as a typed value; a bad one is ignored with a warning naming it, and the default kept. Files written by every earlier version (`KEY=%q` lines; `KEY="..."` or `KEY='...'` edited by hand) still load. Before anything is built, run or written, install checks once more that every unit setting is usable as it is - the backstop of Kamino 196, which stops with no unit and no `daemon-reload`.
- **The defaults are the deployment**: re-running `install` on a rebuilt host has to bring back the same service, so a lasting change belongs in the script's defaults, not only in the settings file.
- Config: `~/.config/protocol-tui/protocol.conf`; sources: `~/.cache/scomp-link/protocol-build/`
- Commands: `install`, `status` (units, image commits, API health, lingering, firewall, every backend, queue depths and dead letters), `test` (a small CSV through markitdown and back, then removed), `secrets`, `build`, `logs`, `config`, `uninstall` (keeps the model cache and the secrets unless you confirm; never touches meksha or the NAS)
